# Examples

Small, synthetic artefacts used by the container composition and the docs. Nothing here is real
correspondence; all of it was generated by the CLI in this repository.

## `watermarked-sample.txt`

A fictional incident note with a real GlyphMark mark embedded (channel `zw-octal`, payload
`ticket=2026-09-24/118;class=synthetic`). The invisible code points are in the file, so:

```console
$ uv run glyphmark detect --text-file examples/watermarked-sample.txt
risk=100/100  verdict=watermark-confirmed  suspect_codepoints=126  codepoints=658
```

It exists so the defensive path can be demonstrated without inventing a scenario at runtime:

```bash
# the compose `gate` service: fail the pipeline over a risk threshold (exit 6 = threshold hit)
docker compose run --rm gate

# the same thing on the host
uv run glyphmark detect --text-file examples/watermarked-sample.txt --fail-on-risk 25; echo "exit=$?"

# and the sanitization half: after stripping, the same text scans clean
uv run glyphmark sanitize --text-file examples/watermarked-sample.txt -o /tmp/clean.txt
uv run glyphmark detect --text-file /tmp/clean.txt
```

Regenerate it (the mark changes with the payload, so the byte offsets move):

```bash
uv run glyphmark encode \
  --cover-file examples/watermarked-sample.txt \
  --payload 'ticket=2026-09-24/118;class=synthetic' \
  --scheme zw-octal --placement spread \
  -o examples/watermarked-sample.txt
```

A keyed variant, for the "only the recipient can read it" case:

```bash
uv run glyphmark encode --cover-file examples/watermarked-sample.txt \
  --payload 'session=4F2A' --scheme tags --key "$GLYPHMARK_KEY" -o /tmp/keyed.txt
uv run glyphmark decode --text-file /tmp/keyed.txt --key "$GLYPHMARK_KEY"
```

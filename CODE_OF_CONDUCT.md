# Code of Conduct

GlyphMark adopts the **[CNCF Code of Conduct][coc]** (v1.0), which is also the Cloud Native
Computing Foundation's project code of conduct and is derived from the Contributor Covenant.

[coc]: https://github.com/cncf/foundation/blob/main/code-of-conduct.md

## Where it applies

It applies to all project spaces: GitHub issues and pull requests, the maintainers' and
contributors' communications, talks and demos about the project, and any event where an individual
is representing GlyphMark.

## The part that matters most for this project

GlyphMark is a security research tool: it demonstrates how to hide data in text and how to find it.
That means real abuse questions will land in issues. Please:

* discuss attack techniques at the level needed to improve the defence, and not as a step-by-step
  guide for harming people;
* never post a *real* watermarked document belonging to someone else — use synthetic text;
* do not use issues to disclose unpatched vulnerabilities; see [SECURITY.md](SECURITY.md);
* assume good faith in detection false positives: confusable detection touches non-Latin scripts,
  and a report that reads as an accusation against a language community will be edited.

## Reporting

Report incidents to the maintainers listed in [MAINTAINERS.md](MAINTAINERS.md) using the contact
information there, or through any maintainer you trust. Reports may also be sent to the CNCF
conduct team at <cnc-fcoc@cncf.io> if you would rather not involve project maintainers.

Maintainers will acknowledge reports within 5 working days, will keep the reporter's identity
confidential unless consented otherwise, and may request (or take) remedies including edits,
temporary exclusion from discussions, or a ban from project spaces. Escalation follows the CNCF
process: the project maintainers first, then the CNCF Code of Conduct Committee
(<cnc-fcoc@cncf.io>).

## Enforcement consequences

| level | response |
|---|---|
| 1 · correction | private written warning, public clarification if the harm was public |
| 2 · warning | written warning with a specified time of behavioural cooling-off |
| 3 · temporary ban | temporary exclusion from project spaces, with a stated path back |
| 4 · permanent ban | permanent exclusion from project spaces and representation of the project |

Decisions are recorded publicly only in anonymised summary form, so that accountability never
reveals who reported what.

This document is versioned; changes follow [GOVERNANCE.md](GOVERNANCE.md) and require a maintainer
majority plus notice in the public channel.
